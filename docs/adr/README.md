# Architecture Decision Records

Architecture Decision Records (ADRs) capture durable, reviewable architectural decisions for EngramMesh. Each ADR is an immutable, numbered Markdown document in this directory. Do not renumber, rewrite, or delete an accepted record; create a new ADR that supersedes it when the decision changes.

## Statuses

Every ADR must use one of these statuses:

- `proposed`: open for review and not yet adopted.
- `accepted`: adopted and authoritative until superseded.
- `superseded`: replaced by a later numbered ADR, which must be linked.
- `rejected`: considered but not adopted, with its rationale preserved.

## Creating an ADR

Use the next available number and a concise, descriptive filename. Include the context, decision, alternatives considered, consequences, status, date, and links to the relevant issue, RFC, or pull request. Submit it for public review before changing the architecture it records.
