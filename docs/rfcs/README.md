# Request for Comments

RFCs provide a public, reviewable path for changes that need project-wide discussion before implementation. Store each RFC as a Markdown document in this directory and link its issue or pull request discussion.

## When an RFC is required

An RFC is required for changes to:

- public APIs;
- event compatibility;
- storage interfaces;
- security boundaries;
- licensing; or
- governance.

An RFC should state the problem, goals and non-goals, proposed design, alternatives, compatibility and security effects, migration or rollout plan, and unresolved questions. Link related ADRs and implementation pull requests.

## Public review

After the repository becomes public, an RFC must have a minimum seven-calendar-day public comment period before acceptance. Maintainers record the outcome and rationale in the RFC discussion or the accepted RFC. Urgent security handling may use the project's private disclosure process, followed by a public record when it is safe to publish.
